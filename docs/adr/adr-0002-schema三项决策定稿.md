# ADR-0002 · schema 三项决策定稿

## 上下文

架构 v0.2 遗留 4 项待拍板：语义锚点（已随 v0.2 定稿）、机检"内容一致性"验证方式、模块边界、重做预算。2026-10-01 用户逐项拍板，三项决策定稿。

用户基调（拍板依据）：**"视频最基础的内容做好就可以，剩下的内容由人手动修改、手动审查"**；**"不需要把机制想得特别完美，只有现实问题才会暴露更多错误"**——机制先跑起来，数据驱动迭代。

## 决策

### 1. 机检"内容一致性"验证 = 混合 + 视觉保底

- 规则查全部硬指标（坐标/时长/编码/锚点合法）；
- LLM 摘要比对（执行器产物文本摘要 vs 语音关键词）；
- **视觉模型截图保底**：执行器产物直接抽帧截图，交给视觉模型做语义分析（画面内容 vs 语音/字幕是否对应）——比纯文本摘要更硬，是最后一道自动兜底。

### 2. 模块边界 = 渐进式 + 外部优先

- 项目初期手动为主（70-80% 手动操作可接受）；
- 执行器**全部用外部 API / 外部执行器**（含本地 CLI，如 faster-whisper/ffmpeg/Remotion）测试选优，找到最合适的；
- 在后续不断确认步骤中把真正的工作流确定下来后，才考虑编写/自建；**自建 = 定死，后置**。

### 3. 重做预算 = 绑定机检失败基线

- 触发条件 = **机检失败项**（基础内容没做好，清单 = 架构 v0.2 §4.2 检查项：粗剪/转录/契约/单事件/合成五类）；
- **人审驳回 ≠ 自动重做**：人审驳回（质感/风格/审美）由人手动修改 overrides.json（锚定词级），不消耗自动重做预算；
- 次数：MVP 统一 3 次，跑真实素材后按各类型实际失败率调整（生成式事件失败率高可加，程序化事件可减）；
- 耗尽 → `stuck` 标记"人工接管"，不阻塞其余事件（NFR-03 不变）。

## 理由

1. **机检窄边界（理念 4）**：机检只查"没做错"，但"内容一致"属于没做错范畴，必须自动兜底——规则不够（抓不到语义不符），纯 LLM 文本比对不够硬（有误判），视觉模型截图是直接证据。
2. **模块可替换 + 护城河在决策/契约层（理念 3/5）**：执行器全用现成（外部）方案，护城河在"信号→事件"决策规则与时间轴 JSON 契约；自建只在工作流确认、确有收益时做。
3. **人在回路半闭合（产品定位）**：人只做最终校准——校准对象是"做得好不好"（审美），不是"基础没做好"（机检已自动处理）；重做预算因此只服务机检失败，与人审解耦。

## 后果

- 机检层实现 = 三类校验（规则 + LLM 摘要 + 视觉模型截图），成本略高于纯规则，换来"内容一致"的真自动兜底。
- 执行器初期全外部，MVP 依赖外部 API/CLI（成本/稳定性风险由 NFR-01 模块可替换吸收）。
- 重做预算 MVP 统一 3 次，跑数据后按类型调档；失败率数据写入 review_manifest.json（每事件机检结果留痕）。
- PRD FR-05（机检内容一致性）与 NFR-02（机检可判定边界）按本 ADR 更新。
