# 视频剪辑工作流 Agent · 架构 v0.4 · 双路径体系（需求分析为共同起点）

> 版本：v0.4（2026-10-01）
> 修正方向：从"单一路径的视频剪辑工作流"升级为"**需求分析 → 双路径分支**"的统一体系。
> 触发：用户发现「Opus 代码直出·电影感」这类生成主导动画与"素材辅助剪辑"**不是一个体系**——前者动画即视频的绝大部分内容，后者动效只是引导/解释层。决定：相同的地方共用，不同的地方分支。

## 2. 体系总览（一句话）

**需求分析是唯一共同起点**。输入（意图 + 素材 + 观点）先进需求分析层，产出"路径判断 + 需求规格"；然后拆成两条路径——**路径 A：按用户给的素材处理，辅助素材讲清楚观点**（剪辑 + 引导型动效）；**路径 B：完全画面，动画/画面即视频的绝大部分内容**（文生图/多参生图组装，或强模型直接代码直出）。两条路径共用编排层、时间轴 JSON 契约、机检层、审核层、审美指导与风格预设库；不同之处只在执行器与动效角色。

## 3. 需求分析层（新增，共同起点）

- **输入**：用户意图（要表达什么观点）、素材（有无、形态）、受众与时长等诉求。
- **产出**：
  1. **路径判断**：A（素材辅助）还是 B（生成主导）；
  2. **需求规格**：时长、风格基调（从风格预设库选）、语气、字幕/配音方式。
- **判断依据**（延续 v0.3 语义路由，一句话判断，不做过细规则）：
  - 用户提供了可用素材、且诉求是"把这个素材/观点讲清楚" → **路径 A**；
  - 无素材、或诉求是"直接做出一个画面/动画表达"（素材只作为参考或完全不需要）→ **路径 B**。
- 配音不是路径分歧点：B 路径的配音（AI 配音或人手动配音）是简单后置项。

## 4. 共用骨架（两条路径相同的地方）

| 共用模块 | 内容 | 状态 |
|---|---|---|
| 编排层 | 需求分析 → 任务拆解 → 生成**时间轴 JSON 契约**（语义锚点为主键、绝对秒为派生缓存） | 现有（v0.2） |
| 机检层 | 规则硬指标 + LLM 摘要比对 + **视觉模型截图保底**（ADR-0002 ①）；只判基础质量不判审美 | 现有（ADR-0002） |
| 审核层 | 人审工作台（关键帧 + 单事件产物 + 粗成片）；驳回理由沉淀为约束，只增不减 | 现有（v0.2） |
| 审美指导 | aesthetic-guide.json：色板/字体/特效/风格方向与限制 | 现有（v0.2 设计） |
| 风格预设库 | style-presets.json，**每条约预设增加 `path` 字段（material / generate）** | 本次修正（v0.1→v0.2） |
| 评审留痕 | review_manifest.json / overrides.json（锚定词级，人审改动不消耗自动重做预算） | 现有（v0.2） |
| 模块边界 | 执行器全外部优先，自建后置（ADR-0002 ②）；重做预算绑定机检失败基线（ADR-0002 ③） | 现有（ADR-0002） |

## 5. 路径 A · 素材辅助（现状主线）

- **定位**：用户给素材，AI 辅助素材讲清楚观点。动效是**引导/解释层**，服务素材内容。
- **管线**（v0.2 全量保留）：素材 → 转录（faster-whisper 词级 `--word_timestamps True`）→ 规则生成 cut-list.json → ffmpeg 抽段 re-encode + concat → 字幕重映射 → 动效编排（overlay / card / diagram / illustration 四类引导型动效）→ 机检 → 人审。
- **执行器**：faster-whisper、ffmpeg、Remotion 官方 skill（overlay/card/diagram 主执行器候选）、风格预设（`path: material`）。
- **动效角色**：注意力引导 + 解释（圈选/关键词卡/结构图/科普插画），动画不主导内容。

## 6. 路径 B · 生成主导（新增支线）

- **定位**：无素材或纯画面表达，动画/画面即视频的绝大部分内容；配音（AI/人）后置。
- **两条子路径**：

### 6.1 子路径 B1 · 图像生成组装

- 文生图 / 多参生图（seedream 类模型）逐场景生成关键画面 → 按时间轴 JSON 组装（转场/运镜/节奏可配代码）→ 配音对齐。
- 适用：单张信息密度高、画面即内容（科普插图、概念展示、MV 分镜）。
- 风险：场景间一致性（同主体跨场景），需以首图为核心资产做 image_edit 延展或显式风格锁定。

### 6.2 子路径 B2 · 代码直出（Opus 5.5 / Claude 类强模型）

- 强模型直接写代码 → 浏览器 / Remotion / Three.js / GLSL 逐帧渲染 → ffmpeg 合成 MP4（"帧 = 同一函数算出来的"，天然连贯）。
- **节拍表（beat sheet）方法论**：画面、配乐、音效共用同一张节拍表，所有切点踩拍（Clawd 教程核心；宝玉xp《中华文明史》配乐当时钟为同族方法）。
- 同源多风格参数化：风格作为参数切换（JUST CODE 六风格先例），不重写 pipeline。
- 适用：情绪化/电影感/整片级动画（用户认可的"眩晕、瘫坐、原子弹爆炸"气质即属此类）。
- 已入风格预设：`opus-code-cinematic`（`path: generate`）。
- 约束：需 headless 浏览器/GPU 渲染环境；长视频渲染成本高（MVP 建议 ≤60s 片段验证）；错误是系统性的（抽帧验收）。

## 7. 两条路径的分与合

| 维度 | 共用（两条路径相同） | 路径 A 素材辅助 | 路径 B 生成主导 |
|---|---|---|---|
| 起点 | 需求分析层 | — | — |
| 编排 | 任务拆解 + 时间轴 JSON 契约 | 事件=引导型动效（overlay/card/diagram/illustration） | 事件=场景/镜头/动画段（anim） |
| 素材 | 素材角色由需求分析判定 | 素材是主体，动效辅助 | 无素材或素材仅参考，画面即主体 |
| 执行器 | 外部优先、可替换 | 剪辑（whisper/ffmpeg）+ 引导动效（Remotion） | 生图组装（seedream 类）/ 代码直出（Claude/GLSL/Remotion） |
| 动效角色 | — | 引导/解释层 | 主导层（动画=内容） |
| 配音 | 后置简单项（AI 或人） | 保留原声/配音 | AI 配音或人配 |
| 机检/审核 | 同一机检基线 + 同一人审沉淀 | 同 | 同 |

## 8. style-presets.json 修正（v0.1 → v0.2）

- 每条预设新增 **`path`** 字段：`material`（路径 A 素材辅助）/ `generate`（路径 B 生成主导）。
- 现有条目 `opus-code-cinematic` 标记为 `path: generate`。
- 后续新增预设（video-shotcraft 风格、HyperFrames 模板）按实际归属打标；风格预设库仍由制作前人选基调。

## 9. 待拍板 / 下一步

1. **路径 B 的 MVP 切入点**：建议从 B2 代码直出开始（≤60s 片段），与 A 路径共用编排/机检/审核验证；B1 图像组装的一致性方案（核心资产延展）待实测。
2. **需求分析层颗粒度**：路径判断的输入字段定义（素材有无/形态、内容形态、时长）——先以编排层语义一句话判断起步，跑数据后细化。
3. **时间轴契约的双路径差异**：A 事件=引导动效，B 事件=场景/动画段——统一 schema（事件类型扩展）还是各自子 schema，待 B 路径 MVP 验证后定。
4. 风格预设库继续扩充（video-shotcraft 214 styles / HyperFrames 模板按 path 归组）。
