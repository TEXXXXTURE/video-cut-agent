# 剪辑工坊（video-cut-agent）

> 人在回路的半闭合视频剪辑工作流 Agent：语义驱动的智能剪辑 + 引导型动效编排。

剪辑工坊是一套可搭建、可运行的视频自动剪辑与动效编排工作流。"AI 初剪 → 动效编排 → 机检 → 人审校准"被拆成独立模块，以时间轴 JSON 为唯一契约。剪辑、动效、字幕、审核各环节可替换、可测试、可逐步自动化。

项目采用模块化设计。核心价值在"信号 → 事件"的决策规则与时间轴契约层；执行器全部外置、可替换。

## 背景

社区在 AI 剪辑上的共识管线是转录驱动剪辑（Descript → AutoCut → 2026 的 agent skill / 本地 CLI 爆发）：录一段完整视频 → 转录 → 按时间区间整体切除 + 字幕重映射 → 得到初剪。这一层已经成熟。

本项目的范围在剪辑之外的动效与内容配合：圈选标注、关键词卡、结构图、解释插画、动画帧这类"注意力引导层"与"解释层"。它们是视频从"能看"到"好看、好懂"的关键。

## 核心设计

### 双路径体系（v0.4）

需求分析是两条路径的共同起点：输入（意图 + 素材 + 观点）→ 需求分析层 → 路径判断。

- **路径 A · 素材辅助**（现状主线）：提供素材时，辅助素材讲清楚观点。剪辑 + 引导型动效（overlay/card/diagram/illustration），动效是引导/解释层。
- **路径 B · 生成主导**（新增支线）：无素材或纯画面表达时，画面即视频的绝大部分内容。子路径 B1 文生图/多参生图组装；子路径 B2 强模型代码直出（Opus 5.5/Claude → 逐帧渲染 → ffmpeg，节拍表对齐画面/配乐/音效）。

两条路径共用：编排层、时间轴 JSON 契约、机检层、审核层、审美指导、风格预设库（预设按 `path: material/generate` 打标）。不同的只有执行器与动效角色。详见 [v0.4 文档](视频剪辑工作流Agent-架构搭建-v0.4-双路径体系与生成路径.md)。

### 四层架构 + 内核循环

```
┌─────────────────────────────────────────────────────────┐
│                   编排层（Orchestrator）                  │
│   语义路由一句话判断 → 拆解任务 → 生成时间轴 JSON 契约     │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│                   执行层（Executors）                     │
│   剪辑（faster-whisper + ffmpeg） ／ 动效（overlay/anim）  │
│   字幕重映射 ／ 风格预设注入（aesthetic-guide.json）        │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│                   机检层（Machine Check）                 │
│   规则硬指标 + LLM 摘要比对 + 视觉模型截图保底             │
│   只判"基础内容没做好"，不判审美                           │
└────────────────────────┬────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────┐
│                   审核层（Human Review）                  │
│   人看关键帧 + 单事件产物 + 粗成片 → 批准/驳回             │
│   驳回理由沉淀为审美约束（只增不减）                       │
└─────────────────────────────────────────────────────────┘
```

内核是一个状态机循环：`pending → planned → executing → checking → reviewing → done`，含 `redoing / stuck`。每一步由前一步的产物驱动，失败有预算、可重试、可人工接管。

### 时间轴 JSON —— 唯一契约

- **语义锚点是主键，绝对秒是派生缓存**（不是反过来）
- 词级时间戳（faster-whisper `--word_timestamps True`）解决字幕漂移
- 事件 = 锚点 + 类型 + 参数，动效执行器只认这个契约
- 人审改动写 `overrides.json`（锚定词级），不消耗自动重做预算

### 五类动效（引导型 + 解释型）

| 类型 | 说明 | 例子 |
|---|---|---|
| overlay | 画面上的引导标注 | 圈选、箭头、高亮 |
| card | 关键词/信息卡 | 字幕条、术语卡、标签 |
| diagram | 结构可视化 | 思维导图、流程图、数据图 |
| illustration | 解释型插画 | 没见过的东西做成示意图展示 |
| anim | 程序化动画 | 场景级代码动画（代码即视频） |

质感由三层保障构成：组件库（决定下限）、审美指导（方向约束，驳回理由沉淀）、参考素材（目标对齐）。

### 三个已拍板的关键决策（ADR-0002）

1. **机检内容一致性 = 混合 + 视觉保底**：规则硬指标 + LLM 摘要比对 + 视觉模型截图做语义分析
2. **模块边界 = 渐进式 + 外部优先**：初期 70-80% 手动可接受，执行器全用外部 API/CLI 测试选优，自建后置
3. **重做预算 = 绑定机检失败基线**：只判"基础内容没做好"，人审驳回由人手动改，MVP 统一 3 次、跑数据后调档

## 当前状态

- 架构 v0.4 定稿（双路径体系），schema 三项决策已拍板（ADR-0002）
- 社区调研完成：转录驱动剪辑是主流；执行器必须 CLI/脚本（SaaS/NLE 不可编程）；关键参考 [ossclip](https://github.com/chenxwh/ossclip)
- 动效选型调研完成：代码即视频（Claude 逐帧案例核实）、Remotion 生产级采用证据、video-shotcraft / HyperFrames 风格库对标
- 风格预设库 v0.2 落地（2026-10-01）：`style-presets.json` 首条「Opus 代码直出 · 电影感」（`path: generate`）——源自 Opus 5.5 直出动画潮（抖音 Vibe 知识大赏同族），含节拍表方法论（画面/配乐/音效同一张 beat sheet）与六步制作流程参考
- MVP 未启动：按 ADR-0002，用外部执行器（faster-whisper + ffmpeg + Remotion 官方 skill）跑通"转录→cut-list→粗剪→字幕重映射"，初期手动为主

## 路线图

1. **MVP 剪辑管线**：真实口播素材跑通转录 → cut-list → ffmpeg → 字幕重映射，实测规则参数（VAD 500ms / 删静音 ≥1.5s / 最短保留 0.5s）
2. **风格预设库扩充**：继续收录 video-shotcraft 214 styles / HyperFrames 模板 / Clawd 节拍表方法论，制作前人选风格
3. **动效执行器原型**：Remotion 官方 skill 为主，代码即视频为渲染层候选
4. **机检 + 人审工作台**：规则 + LLM 摘要 + 视觉模型截图；驳回理由沉淀回审美指导
